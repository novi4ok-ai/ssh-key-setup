# SSH Key Setup

Linux-утилита на Go для настройки SSH-доступа. Основной режим — **консоль**, с интерактивным мастером и параметрами командной строки. Дополнительно доступен русскоязычный графический интерфейс Fyne.

Создаёт ключ Ed25519 (по умолчанию **без парольной фразы**, с `-protect-key` — зашифрованный), устанавливает открытую часть через SFTP, проверяет вход отдельным SSH-подключением только по ключу и настраивает обычную команду `ssh пользователь@адрес` или `ssh имя`. Программа работает на компьютере, **с которого нужно подключаться**; закрытый ключ остаётся на нём.

## Быстрый запуск

Проверка уже настроенного доступа без изменения SSH-файлов и без пароля сервера:

```bash
./dist/ssh-key-setup -check -ip 192.0.2.10 -u root
```

Диагностика проверяет вход существующим ключом и сравнивает адрес, пользователя, порт и ключ с результатом системного `ssh -G`. Требуется установленный OpenSSH-клиент. Пользовательские директивы `Match exec` обрабатываются самим OpenSSH, поэтому конфигурация должна быть доверенной.

```bash
# Показать справку, параметры, примеры и рекомендации по безопасности
./dist/ssh-key-setup

# Все данные заданы: немедленная настройка в консоли, без дополнительных вопросов
./dist/ssh-key-setup -ip '192.0.2.10' -u 'root' -p '12345'

# Нестандартный порт: -p означает пароль, -port — порт SSH
./dist/ssh-key-setup -ip '192.0.2.10' -u 'root' -p '12345' -port 2222

# Пароль будет запрошен скрыто в терминале
./dist/ssh-key-setup -ip '192.0.2.10' -u 'root'

# Принудительно открыть консольный мастер, даже на рабочем столе
./dist/ssh-key-setup -cli

# Открыть графический интерфейс
./dist/ssh-key-setup -gui

./dist/ssh-key-setup -help
```

IP в примерах нужно заменить адресом своего сервера. Если программа установлена в `PATH`, префикс `./dist/` не нужен. Запускайте от пользователя, которому нужен доступ: ключи сохраняются в его `~/.ssh`, права администратора приложению не требуются.

Пароль в `-p` может быть виден в истории оболочки и аргументах процесса. Чтобы не передавать его в аргументах, опустите `-p` для скрытого ввода или используйте `-password-stdin`:

```bash
ssh-key-setup -ip '192.0.2.10' -u 'root' -password-stdin < /path/to/password-file
```

Из stdin читается одна строка: LF/CRLF в конце удаляется, пробелы сохраняются. `-p` и `-password-stdin` нельзя совмещать. Порт по умолчанию — 22; полный мастер через `-cli` предлагает изменить его.

При повторном запуске без `-p` и `-password-stdin` программа сначала пробует сохранённый ключ. Если вход работает, она восстанавливает локальный SSH config без пароля и без изменения серверного `authorized_keys`. Если сервер отклоняет ключ, в терминале запрашивается пароль; без терминала выводится ошибка с указанием способов его передачи. Явно заданный пароль сохраняет режим настройки через пароль. При смене ключа сервера или сетевой ошибке перехода к запросу пароля нет.

## Режимы и параметры

До настройки можно посмотреть план: `ssh-key-setup -dry-run -host server.example.com -u ubuntu -alias work`. Предпросмотр не подключается к серверу, не запрашивает пароль и не создаёт файлы. Он показывает новый или существующий ключ и будущий блок SSH config. Наличие ключа на сервере и необходимость резервной копии определяются только при настоящей настройке. `-dry-run` нельзя совмещать с `-check` или источником пароля сервера.

`-host` принимает IPv4, IPv6 и DNS-имена (для международных имён используйте punycode). Старый `-ip` также работает. Не указывайте оба параметра одновременно.

```bash
ssh-key-setup -host server.example.com -u ubuntu -alias work
# После успешной настройки:
ssh work
```

`-alias` сохраняет отдельную секцию SSH config. Для нескольких портов одного сервера задавайте разные имена, например `work` и `backup`. Повторная настройка того же имени обновляет его секцию. Для диагностики передавайте исходный адрес, пользователя, порт и то же имя: `-check -host server.example.com -u ubuntu -alias work`.

| Параметр | Назначение |
| --- | --- |
| `-host` | IPv4, IPv6 или DNS-имя; альтернатива `-ip` |
| `-alias` | Имя подключения для команды `ssh имя` |
| `-check` | Проверка существующего доступа и конфигурации без изменения SSH-файлов |
| `-dry-run` | Локальный предпросмотр без сети и записи файлов |
| `-fingerprint` | Ожидаемый отпечаток сервера в формате `SHA256:…` |
| `-confirm-host-key` | Подтверждение нового ключа сервера в терминале |
| `-protect-key` | Парольная фраза для нового ключа |
| `-passphrase-file` | Защищённый файл с фразой нового или существующего ключа |
| `-agent` | Использование ssh-agent; добавление разблокированного ключа на час |
| `-ip` | IPv4 или IPv6 сервера |
| `-u` | Пользователь на сервере |
| `-p` | Пароль сервера |
| `-port` | Порт SSH, по умолчанию 22 |
| `-cli` | Интерактивный консольный мастер |
| `-gui` | Графический интерфейс; ошибка, если он недоступен |
| `-password-stdin` | Пароль из первой строки стандартного ввода |
| `-timeout 2m` | Тайм-аут консольной настройки; по умолчанию `90s` |
| `-help`, `-h` | Справка |
| `-version` | Версия |

Также принимается двойной дефис, например `--help`. Запуск без аргументов выводит полную справку в stdout и завершается с кодом `0`, независимо от наличия графической сессии. Параметры подключения сразу запускают консольную настройку. `-gui` не совмещается с параметрами консольного режима и требует соседний модуль `ssh-key-setup-gui`.

В консоли пять этапов и сведения о ключе/резервной копии выводятся в **stderr**, а проверенная команда подключения — в **stdout**. Коды завершения: `0` — успех/справка/версия/обычное закрытие GUI; `1` — ошибка настройки или запуска GUI; `2` — ошибка параметров/ввода; `130` — отмена. Ctrl+C и SIGTERM отменяют консольный ввод или подключение; скрытый ввод восстанавливает отображение символов в терминале.

## Linux и готовые файлы

В GUI доступны «Проверить доступ», «Предпросмотр», поле имени подключения и раздел «Дополнительная защита». Пароль сервера и парольная фраза ключа запрашиваются отдельно, когда нужны. При создании защищённого ключа фразу нужно повторить; новый ключ сервера можно подтвердить в отдельном окне. Предпросмотр автоматически раскрывает подробности и не показывает сообщение об успешной установке.

Основной `dist/ssh-key-setup` — **статический Linux amd64 ELF**, собранный с `CGO_ENABLED=0`. Для него не нужны Go, glibc, X11, Wayland или OpenGL. Проверки запуска проведены в контейнерах Debian 12/13, Ubuntu 22.04/24.04/26.04 LTS и AlmaLinux 8/9/10. Это проверка пользовательского окружения на общем ядре хоста, а не отдельных ядер всех дистрибутивов. [Подробности проверок](docs/VALIDATION.md).

Графика вынесена в **дополнительный `ssh-key-setup-gui`**, который нужно хранить рядом с основным файлом. Основной файл запускает его по параметру `-gui`; для сервера достаточно одного `ssh-key-setup`. Это позволяет запускать консоль даже на машине без графических библиотек.

Переносимая GUI-сборка через `make build-compatible` выполняется на AlmaLinux 8 с базой glibc 2.28 и использует X11/OpenGL; в Wayland нужен XWayland. Она требует системных графических библиотек. На Debian/Ubuntu это обычно `libgl1`, `libx11-6`, `libxcursor1`, `libxrandr2`, `libxinerama1`, `libxi6`, `libxxf86vm1`; на AlmaLinux — `mesa-libGL`, `libX11`, `libXcursor`, `libXrandr`, `libXinerama`, `libXi`, `libXxf86vm`. На обычном рабочем столе они, как правило, уже есть. Проверить конкретный GUI-файл можно через `ldd dist/ssh-key-setup-gui`.

Для другой архитектуры нужен отдельный файл. Минимальные требования Go к ядру Linux приведены в [официальной документации](https://go.dev/wiki/MinimumRequirements).

На сервере нужны SSH с разрешённым входом по паролю, SFTP, Ed25519 и возможность записать `~/.ssh/authorized_keys`. Для замены существующего файла требуется расширение SFTP `posix-rename@openssh.com`, которое поддерживает OpenSSH. MFA, нестандартный `AuthorizedKeysFile`, chroot/SFTP-only или дополнительные требования аутентификации могут потребовать ручной настройки. Утилита не меняет `sshd_config` и не отключает парольный вход.

## Сборка

Для консоли нужен только Go 1.26.8 или новее:

```bash
make build
./dist/ssh-key-setup -cli

# Без make
CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o dist/ssh-key-setup ./cmd/ssh-key-setup

# Консоль для ARM64
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -o dist/ssh-key-setup-arm64 ./cmd/ssh-key-setup
```

Комплект с графическим модулем для распространения на указанных amd64-дистрибутивах собирается через Docker:

```bash
make build-compatible
```

Команда использует `Dockerfile.desktop` и экспортирует оба файла вместе с `SHA256SUMS` в `dist/`. Нужен доступ к Docker; Go и графические заголовки на хосте не требуются.

Для локальной GUI-сборки на Debian/Ubuntu:

```bash
sudo apt-get install build-essential pkg-config libgl1-mesa-dev xorg-dev \
  libwayland-dev libxkbcommon-dev wayland-protocols
make build-desktop
./dist/ssh-key-setup
```

`make build-desktop` использует CGO для графического модуля и библиотеки текущей системы: такой GUI-файл может не запуститься на более старой glibc. Для распространения используйте `make build-compatible`. Зависимости зафиксированы в `go.mod` и `go.sum`.

## Что проверяется

### Дополнительная защита

```bash
# Сверка ожидаемого отпечатка до отправки пароля сервера
ssh-key-setup -host server.example.com -u ubuntu -fingerprint 'SHA256:ОТПЕЧАТОК'

# Новый сервер нужно подтвердить в терминале; новый ключ будет зашифрован
ssh-key-setup -host server.example.com -u ubuntu -confirm-host-key -protect-key -agent

# Повторный вход с ключом, уже разблокированным в ssh-agent
ssh-key-setup -host server.example.com -u ubuntu -agent
```

Настоящий SHA256-отпечаток нужно получить по доверенному каналу, например в консоли провайдера. `-fingerprint` не отменяет проверку уже сохранённого `known_hosts`: сменившийся ключ всё равно отклоняется. `-confirm-host-key` запрашивает `yes` только для неизвестного сервера. Без этих параметров сохраняется автоматическое принятие первого ключа.

`-protect-key` шифрует **новый** ключ в формате OpenSSH; фраза вводится скрыто с повторным вводом. Существующие ключи не перезаписываются: для уже незашифрованного ключа этот флаг выдаст ошибку. Зашифрованный существующий ключ можно открыть скрытым вводом или `-passphrase-file /путь/к/файлу`. Файл должен принадлежать текущему пользователю, иметь права 600/400 и содержать одну непустую строку до 4096 байт; ссылки отклоняются. Пароль сервера и парольная фраза ключа — разные значения.

`-agent` требует уже запущенного `ssh-agent` и `SSH_AUTH_SOCK`. Программа использует только ключ, соответствующий выбранному локальному файлу, и добавляет разблокированный или созданный ключ в агент на один час. В режиме `-check` ключи в агент не добавляются. Сам агент не запускается и на сервер не перенаправляется. Формат защищённого ключа предоставляется [библиотекой SSH](https://pkg.go.dev/golang.org/x/crypto/ssh#MarshalPrivateKeyWithPassphrase); время хранения ключей поддерживается [OpenSSH ssh-agent](https://man.openbsd.org/ssh-add#t).

- Адрес: IPv4/IPv6 или DNS-имя, удаление пробельных символов по краям, запрет пробелов внутри, неопределённых, multicast и широковещательного IPv4-адреса. IPv6 zone ID не принимаются.
- Порт: цифры, диапазон 1–65535, значение по умолчанию 22.
- Логин: очистка по краям и консервативный формат Linux-имени — латинская буква или `_` в начале, далее буквы, цифры, `_`, `.`, `-`, необязательный `$` в конце. Основная часть до 64 символов.
- Пароль: не пустой, до 4096 байт, без NUL и переносов строк. **Пробелы, включая начальные и конечные, сохраняются.** Приложение не записывает пароль в настройки, файлы или журнал и не передаёт его дочернему GUI. Явная передача через `-p` оставляет его в аргументах основного процесса. Во время операции пароль находится в памяти; полное затирание всех копий строк в памяти Go не гарантируется.
- Первый ключ сервера автоматически принимается и сохраняется в пользовательском `~/.ssh/known_hosts` с хешированным адресом. Последующие подключения проверяются. Изменённый или отозванный ключ отклоняется **до отправки пароля**. Повреждённый файл доверия не перезаписывается. Автопринятие первого ключа не защищает от подмены при самом первом соединении. Системный `/etc/ssh/ssh_known_hosts` в этой версии не используется.
- Локальные `.ssh` и файлы: владелец, тип, права `700`/`600`, отказ от символических и жёстких ссылок на файлы; существующие закрытые ключи не перезаписываются. Одновременный запуск блокируется через `flock`.
- На сервере: проверка типа и владельца `.ssh`/`authorized_keys`, права `700`/`600`, ограничение размера файла 4 МиБ. Все операции выполняются через SFTP, без подстановки пользовательского ввода в shell-команды.
- Перед изменением существующего `authorized_keys` создаётся точная резервная копия `authorized_keys.backup-<случайный суффикс>` с правами `600`. Обновление выполняется через временный файл и атомарное переименование. Комментарии и старые записи сохраняются.
- Повторный запуск для той же комбинации IP, порта и логина использует тот же локальный ключ и не добавляет дубликаты. Если такой ключ уже имеет ограничения (`restrict`, `command=...` и другие), операция останавливается, не обходя их.
- После успешной проверки в начало пользовательского `~/.ssh/config` атомарно добавляется управляемый блок с IP, логином, портом и `IdentityFile`. Существующие настройки сохраняются. Повторный запуск обновляет свой блок без дубликатов. Символические и жёсткие ссылки на `config` отклоняются.
- Тайм-аут каждого подключения — 25 секунд, включая SSH/SFTP; всей операции в GUI — 90 секунд. В CLI общий тайм-аут задаётся через `-timeout`, по умолчанию также 90 секунд. Отмена закрывает сетевое соединение. Окно и терминал остаются отзывчивыми.
- После установки выполняется новое соединение с единственным методом аутентификации — сгенерированным ключом. Проверяется тот же ключ сервера. Только после этого показывается успех и команда подключения.

## Какие файлы создаются

Домашние каталоги с переносами строк, NUL или последовательностью `${` отклоняются до подключения: такие пути нельзя без искажений записать в используемый формат SSH config. Пробелы, кавычки, обратный слеш и `%` поддерживаются.

Локально:

```text
~/.ssh/ssh-key-setup_<идентификатор сервера и пользователя>_ed25519
~/.ssh/ssh-key-setup_<идентификатор сервера и пользователя>_ed25519.pub
~/.ssh/known_hosts
~/.ssh/config
~/.ssh/.ssh-key-setup.lock
```

Ключи сохранены в формате OpenSSH. Закрытый ключ не отправляется на сервер. Управляемый блок в `~/.ssh/config` позволяет подключаться обычной командой:

```bash
ssh пользователь@IP
```

Для нестандартного порта дополнительный `-p` не нужен: порт берётся из созданного блока. Локальный lock-файл остаётся на диске; действующая блокировка автоматически освобождается при завершении процесса.

На сервере изменяется только каталог `.ssh` пользователя подключения: `authorized_keys`, при необходимости его резервная копия и временные файлы операции. Резервные копии автоматически не удаляются.

## Ошибки и восстановление

Если финальная проверка не прошла, созданный ключ остаётся на компьютере и установленный открытый ключ не откатывается: они могут понадобиться для повторной попытки. Подробности показывают путь к ключу и резервной копии. После потери связи окончательное состояние сервера может быть неизвестно.

Обновления этой утилиты сериализуются пустым каталогом блокировки на сервере: `~/.ssh/.ssh-key-setup.install.lock`. После отмены, обрыва связи или аварийного завершения он может остаться. Убедившись, что другой экземпляр программы не выполняет настройку, удалите **на сервере** только этот пустой каталог:

```bash
rmdir ~/.ssh/.ssh-key-setup.install.lock
```

Локальный файл `.ssh-key-setup.lock` удалять не нужно. Остатки временных файлов `.authorized_keys.ssh-key-setup-*` можно удалить на сервере после проверки завершения операции. Исходный `authorized_keys` не обрезается при ошибке записи временного файла.

Блокировка кооперативная: другие программы, которые её не используют, могут параллельно менять файл. Перед заменой утилита повторно сверяет содержимое, но SFTP не даёт универсальной операции compare-and-swap; не редактируйте `authorized_keys` параллельно с настройкой. Серверные POSIX ACL и расширенные атрибуты при замене файла не копируются.

## Проверки проекта

`make ci` запускает тесты с детектором гонок, статические проверки CLI/GUI, терминальные сценарии, интеграцию с OpenSSH, обе локальные сборки и контрольные суммы. Нужны зависимости GUI и права для изолированного OpenSSH-теста, описанные ниже.

В `.github/workflows/ci.yml` настроены проверки при push, pull request и ручном запуске. Отдельное задание собирает совместимый комплект на AlmaLinux 8, проверяет CLI в восьми Linux-контейнерах и сохраняет бинарники с контрольными суммами как артефакт на 14 дней. GitHub Actions использует только права чтения репозитория; версии действий закреплены по коммитам. Для запуска на GitHub репозиторий должен быть опубликован там с включённым Actions.

```bash
make test          # SSH/SFTP, CLI и GUI с детектором гонок
make check         # go vet и проверка контрольных сумм модулей
make check-desktop # дополнительно go vet для GUI (нужны графические заголовки)
make test-terminal # псевдотерминал: help, мастер, скрытый пароль и Ctrl+C
make test-linux    # запуск в восьми контейнерах Linux (нужен доступ к Docker)
make screenshot    # программный рендер окна в artifacts/window.png
```

Тесты поднимают временный SSH/SFTP-сервер на loopback, без обращения к реальным серверам пользователя. Они проверяют валидацию, сохранность ключей и записей, повторную установку, смену ключа сервера до отправки пароля, неверный пароль, неуспешную финальную аутентификацию, ссылки, ограничения ключей, тайм-ауты, отмену, состояния GUI и копирование команды.

Отдельный тест настоящего OpenSSH:

```bash
sudo apt-get install openssh-server openssh-client python3
make integration
```

Этот тест требует `sudo` без пароля и поддержки `unshare --mount`: он создаёт временного системного пользователя, запускает отдельный sshd только на `127.0.0.1` и случайном порту. В приватном пространстве монтирования тестовый sshd получает разрешение TCP wrappers на loopback; рабочие `/etc/hosts.allow`, `/etc/hosts.deny` и настройки системного sshd не меняются. Временный пользователь, процесс и файлы удаляются после проверки. Не запускайте тест с принудительным `kill -9`, если нужна гарантированная очистка.

Для проверки уязвимостей по актуальной базе:

```bash
go run golang.org/x/vuln/cmd/govulncheck@latest ./...
```

## Структура

```text
cmd/ssh-key-setup/   статический CLI и запуск GUI по параметру
cmd/ssh-key-setup-gui/ отдельный GUI-модуль (build tag gui)
internal/cli/       параметры, консольный мастер, терминал, CLI-тесты
internal/ui/        окно, тема, состояния, GUI-тесты
internal/setup/     валидация, локальные ключи, SSH, SFTP, тесты
scripts/           проверки OpenSSH, терминала и Linux-контейнеров
Dockerfile.desktop сборка комплекта на AlmaLinux 8
```
